# Rust 코어 체크리스트

| ID | Task | Deliverables | Verification | State |
|---|---|---|---|---|
| T1.1 | plan과 이 checklist를 한국어 쌍과 함께 두고 문서를 검사한다. `make docs-check`가 `config/documents.json`의 문서와 `config/checklist.json`의 행을 가진 checklist를 읽고, `make check`와 CI의 항목 `core`가 그것을 실행하며, `make documents-stamp`가 검토된 한국어 쌍의 `source-sha256`을 쓴다. 전에는 어떤 검사도 문서를 읽지 않아서 한국어 쌍이 영어 파일보다 뒤처져도 보이지 않았다 | `docs/plans/rust-core/`, `config/documents.json`, `config/checklist.json`, `Makefile`, `.github/workflows/ci.yml`, `AGENTS.md` | `make docs-check` | [o] |
| T1.2 | 추적 파일은 Git commit을 적지 않는다. commit id는 저장소가 없는 독자에게 아무것도 가리키지 않으므로, 그 규칙을 `AGENTS.md` "Commit과 변경"에 적고 검사한다 | `AGENTS.md`, `tests/scripts/commits.test.mts` | `make test-scripts` | [o] |
| T1.3 | binding의 release에 의존한다. 코어와 바인딩 crate의 `polyspec-binding-core`가 `branch = "v1/rust-core"` 대신 binding 저장소의 `tag = "v0.0.2"`를 적고, binding scaffold가 바인딩 crate를 다시 쓰고, `Cargo.lock`이 그 tag의 commit을 고정하고, `AGENTS.md` "Bindings"가 그 tag를 적는다. binding 0.0.2의 release를 기다린다 | `packages/rust/Cargo.toml`, `packages/*/Cargo.toml`, `Cargo.lock`, `AGENTS.md` | `make install-binding bindings-check` | [v] |
| T1.4 | 0.0.1 다음 version에서 바인딩 패키지를 플랫폼별로 release의 asset으로 낸다. abi3 wheel, PHP 확장, platform package를 가진 npm package, Go 정적 라이브러리가 `config/release.json`의 행이고, `package.json`이 고정하는 kit 0.0.111 이후가 그것을 묶는다. binding 0.0.3 이후가 이 패키지의 release recipe를 생성하고(binding B2.262) `binding release-recipes --root .`이 그것을 Makefile이 include하는 `packages/release.mk`에 쓰며 `binding check`가 CK-94를 내지 않으므로 이 저장소는 자기 recipe를 쓰지 않는다. 브랜치 `lane/release-wasm`의 `config/release.json` 행과 napi CLI를 그 `make release-wasm` 없이 가져오고 브랜치를 지운다. 그 binding 행과 T1.3을 기다린다 | `config/release.json`, `package.json`, `package-lock.json`, `Makefile` | `make release-coverage` | [ ] |
| T1.5 | `main`에서 `ci.yml`의 모든 job을 통과하고, 코어의 annotated tag `v0.0.1`과 `config/release.json`이 적는 tag로 첫 version 0.0.1을 release한다. 바인딩 패키지는 넣지 않고 T1.4가 다음 version에서 더한다. 코어 crate는 http-negotiation, http-form, hyper의 Cargo 의존이 가리키는 Git tag로 release되고, 그 저장소들은 그 tag에서 http-media-type의 바인딩을 빌드한다. 선행 조건: T1.3과 T1.6 | `main`의 CI 실행, release의 tag | `make ci-passed` | [o] |
| T1.6 | release의 브랜치를 `main`으로 만든다. `origin`에 `main`이 없고 `v1/rust-core`가 기본 브랜치이므로, release는 GitHub에서 `v1/rust-core`의 이름을 `main`으로 바꾸고(`gh api -X POST repos/polyspec/http-media-type/branches/v1%2Frust-core/rename -f new_name=main`) 그러면 `main`이 기본 브랜치가 된다. 로컬 브랜치와 그 upstream도 `main`으로 바꾼다(`git branch -m v1/rust-core main`, `git branch -u origin/main main`). 그다음 T1.5의 version commit push가 `ci.yml`이 도는 `main`의 push다 | `origin`의 기본 브랜치, 로컬 브랜치 `main` | `gh api repos/polyspec/http-media-type --jq .default_branch`가 `main`을 준다 | [o] |
